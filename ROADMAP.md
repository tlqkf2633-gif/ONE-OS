# ONE OS roadmap

This roadmap distinguishes working code from research or ideas. Windows stays the host OS; no boot, login, shell, driver, or protected-system changes are in scope.

## 1. Windows interaction validation

Run the current WPF UI on Windows 10/11. Verify main-window controls, resize, focus, dock layering, Explorer/Settings handoff, and DPI behavior; fix observed defects. Add WPF UI automation only after its target Windows test environment is available. Keep `main` unchanged until the owner-reviewed test gate passes.

## 2. Desktop reliability and visual refinement

Add a focused, keyboard-accessible launcher; settings navigation; stable window state behavior; accessible resize cues; persisted user layouts only with safe versioned configuration. Collect owner feedback from an actual Windows run before broad cosmetic replacement.

## 3. Useful first-party utilities

Prioritize a complete ONE Calculator, then ONE Clock and ONE Calendar with local events. Use reusable design tokens. Do not build decorative controls without functionality.

## 4. Windows app and settings handoff

Windows File Explorer and Windows Settings handoff buttons are implemented through fixed launch destinations but are not yet runtime-tested. Verify these on Windows 10/11. Evaluate Samsung Settings only where official distribution and documented support can be verified. Do not claim Galaxy Book detection or Samsung app compatibility until tested on real devices and against official distribution/licensing terms.

## 5. Widgets and system panels

Implement local clock/calendar widgets, notifications generated by ONE OS apps, and quick-setting shortcuts to official Windows settings pages. Hardware toggles require a supported API and real hardware tests; otherwise label them unavailable. Weather requires a configured factual source.

## 6. Setup and application management

Design optional first run, app discovery and installer inspection. Do not execute selected EXE/MSI installers silently or bypass UAC. Show publisher/signature and the exact installer to the user, obtain approval, and distinguish launched/completed/verified outcomes. Windows app cleanup is destructive: require explicit per-package approval, verify Windows-supported removal and rollback, and exclude core/security/runtime components. It is not implemented.

## 7. Samsung and future ecosystem

Research official capabilities per application (Samsung Internet, Gallery, Samsung Settings, Quick Share, Phone Link/mobile apps). Label each Supported, Requirements, Galaxy Book only, Unsupported or Not verified with sources. Distinguish screen mirroring from independent mobile app execution. Build a ONE App Manager foundation only after lawful install/update mechanisms are confirmed. ONE Files and ONE Settings are longer-term replacements, not current claims.

## 8. Updates and release

Add authenticated update, configuration backup/restore, crash reporting/privacy policy and a signed installer only after a reliable Windows release and threat review. Avoid auto-start or shell replacement by default.
